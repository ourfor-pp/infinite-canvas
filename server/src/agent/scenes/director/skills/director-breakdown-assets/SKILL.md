# 导演台资产拆解

素材需求以本次分镜段或制作范围的稳定身份和连续性为准，不遍历 `scene.json.objects` 逐个生图。地面、树干分块、内壁、定位面等预演部件无 `assetId` 不代表缺图；普通部件复用整体场景设计。同一素材的多个实例复用同一身份，按素材与变体去重。实际参与表演但未绑定的角色先复用或建立身份；已明确引用且没有图片才补图，身份存在但未绑定时不得重复创建。只为有独立连续性要求的变化建立变体。

优先读取用户当前分镜段或制作任务的剧情与镜头，再结合当前已保存剧本及其制作拆解识别需要保持一致的角色、场景与关键道具。全剧统筹只整理身份和复用关系，不默认创建或生成全量素材。没有独立一致性要求的普通背景细节写入分镜即可。拆解缺失、内容哈希过期或工程校验存在相关 error 时先报告并修复相关拆解；只有正文确有问题才修订剧本，不从旧拆解继续创建资产。用户已授权完整制作时可衔接对应修订 Skill。先读取素材库，按稳定身份复用同一实体；只为当前需求的缺口建立档案，并在对应定妆帧或视频提示的引用中采用。

角色候选必须区分剧情信息与视觉信息：

- 角色主档“剧情身份”保存身份、关系、首次出现、剧情用途和人物弧光，不作为生图提示词。
- 角色主档“视觉设定”只保存剧本已经明确的稳定可见特征；没有依据时留空，交给角色设计阶段补充。
- 拆解阶段不要把“清秀、俊朗、美女、剑眉星目”等类型化套话当成面部身份；详细面部结构与阵容差异由 `director-design-character` 完成。
- Frontmatter 只保存稳定 ID、显示名称、依赖和 `requiredVariants`；正文摘要保持简短，不把人物小传伪装成视觉描述。
- 角色名称只作为业务标识，不写进生图提示词。

在 `assets/characters/`、`assets/locations/`、`assets/props/` 下按稳定 ID 建立实体文件夹和主档 Markdown，同时建立空白的基础设计 `prompt.md`、空的 `inputs/` 以及 `voice/sound.md` 或 `sound/sound.md`。`prompt.md` 正文是未来原样送模的最终提示词，拆解阶段不得把人物小传、主档摘要或旧 `mediaDrafts` 填进去；必须等对应设计 Skill 完成档案、风格、版式和参考选择后再写。只记录 `requiredVariants` 需求，不创建空白变体目录，也不自动生成媒体。不要用名称相近但身份不同的实体相互覆盖，也不要创建纯气氛词或抽象概念资产。完成后运行工程校验。

仅要求素材拆解时止于档案与需求。粗模预演可在缺图时先交付；用户要求定妆帧、视频样片或完整制作时，自动组合设计和生图能力，先复用、再补齐当前目标必要的角色、场景与关键道具主图，然后继续制作。不把“不阻塞预演”理解成“视频无需素材”，不为其他段全量生图。主要角色需要稳定身份时建立可复用设计，不把临时定妆帧当作角色档案。
