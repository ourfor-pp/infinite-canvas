# 连续性检查

相邻格检查屏幕方向、视线、人物位置、动作接点、道具持有状态、服装伤势、环境时间和光线。同一 Shot 的画格必须表达同一摄影机设置下的动作前、动作中和动作结果；机位、景别或观看方向不连续变化时必须新建 Shot。跨 Shot 时明确唯一硬切时间，并保持场景地理、人物身份与屏幕方向可读。

逐个 Shot 检查实际停留时长。表演还没完成、对白还没说完或听者尚未反应就发生切镜，属于节奏错误；不能以增加画格或缩短镜头解决，应延长视频段或拆成相邻视频段。

故事板始终是一张完整图片，生成或编辑均一次返回整板，不存在逐格独立生成。检查失败先报告问题，再在已有授权范围内针对性修订。

相邻视频段先判断边界类型：普通场景变化使用 `cut`；对白、环境声或音乐跨边界延续由时间线声桥处理；只有同一动作和镜头运动需要无缝延续时使用 `continue`。不要为了“看起来连续”而把所有边界改成首尾帧生成。

审查先判断问题是否破坏剧情动作、人物/道具身份、空间关系或跨段接点；把这些阻断与可调整的导演约定分开记录。左右手、动作细分等约定若不影响物理可行性和上下镜头，可同步修订文字计划；不能把实体穿插、手臂归属不明、道具跳位或剧情动作缺失解释成正常变化。

已有整板大部分正确而仅少数位置错误时，优先尝试以该整板为显式编辑底图，说明必须保留的区域和需要修正的关系，仍一次返回一张完整故事板。相邻段涉及同一空间/状态时实际查看已采用画面，并按需要显式引用，不能只依靠文字约束。定向编辑未通过时记录是否修好原错误、是否引入新错误，再在已授权次数内决定继续编辑或重新设计机位；不以无上限整板重抽代替诊断。

审阅后若只校正文字计划以匹配已经合格的整板，先完成 `segment.md`、`storyboard.yaml` 和 `storyboard-prompt.md` 的修改，再检查实际整板及相邻接点。在同目录 `quality-review.md` 的 Frontmatter 保留工程要求的 `id`、`kind: media-review`，写 `status: accepted` 与 `acceptedInputs`，其 `image`、`storyboard`、`prompt`、`segment` 分别是当前 `storyboard.png`、`storyboard.yaml`、`storyboard-prompt.md`、`segment.md` 原始文件字节的 SHA-256；正文说明审查结论和沿用理由。只对实际看过且符合当前计划的图记录采用，不为绕过阻断填写哈希。程序仅在四项全部匹配时解除故事板过期，不自动放行已有视频；后续任一文件变化或移除绑定都需重新审阅。完成后重新预检，不复制图片、改写数据库或重复生图来清除过期。

采用前必须实际数清整图列数和行数，并与storyboard.yaml layout一致：3x2明确表示三列两行，不是两列三行。普通 Ref2VA 会按该几何裁首格引导，因此排列方向错误会产生跨格引导，不能只改文字阅读顺序后采用，也不能把它当无关版式偏差。实际图不符合受支持布局时，以整板为编辑输入修正到声明布局并重新看图；不要把错误的裁切图交给视频模型。

实际列数、行数与声明相符后，轻微分隔线偏差不单独作为拒绝理由。按当前生成路线检查程序实际使用的裁切：普通 Ref2VA 首帧引导应只含第一格且保留必要人物、动作与空间；当前首尾帧模式取已生成视频的实际边界，不从故事板末格裁图。只有实际引导跨格、关键内容截断或叙事不合格时才要求修复；不要为追求像素级等宽反复生成本已可用的整板。
