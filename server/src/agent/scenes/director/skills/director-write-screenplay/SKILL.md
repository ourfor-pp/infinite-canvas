# 分场剧本创作

先读 [标准分场剧本写作](references/screenplay-craft.md)，再读 `project.yaml`、`story/` 与 `screenplay/`。根据任务选择模式：

- 剧本为空或用户要求从故事重新创作时，只把故事作为创作来源；读取 `screenplay/index.md` 判断现状，不复述或恢复已经被用户要求替换的旧剧本正文。
- 用户要求修订现有剧本时，才读取现有剧本并在其基础上修改。

故事章节是文学叙事单位，不等于剧本场次。动笔前先在内部完成适配规划：列出不可丢失的事件、选择与后果，为各场分配与项目目标相称的表演容量，标明每场独立功能，并检查连续冲突如何改变阻力、信息、策略、代价或人物关系。规划只用于写作，不写入剧本正文。

直接写可阅读、可表演的分场剧本。动作只写观众能看见或听见的内容；对白、沉默、视线、反应和物理动作必须在正文中真实发生。每段对白使用独立的 Markdown 说话者标记：角色名单独一段并写成 `**角色名**`，台词放在紧随其后的普通段落；不得只靠单换行区分人名与台词。每场使用自然的场景标题和正文，不把节拍编号、逐段秒数、场景状态表或素材候选写进文档。

调用更新工具前必须对完整草稿执行一次内部提交检查：

1. 动作段没有解释性心理、作者评价或替观众下结论的叙述。
2. 人物的重大判断与其已经看到、听到的事实一致；若人物否认证据，正文已呈现足以支撑否认的误解、价值冲突或压力。
3. 连续冲突不只是替换人物、地点或道具后重复同一过程。
4. 每场都有不可由相邻场替代的变化，删除后会损失信息、选择、关系、风险或后果。
5. 对白可区分人物，关键动作写出开始、过程和结果，总体表演容量接近项目目标时长。

任一项不满足时先重写草稿，不得仅在回复中宣称“已经递进”“因果完整”或“符合目标时长”。删除或合并无独立功能的场景；原故事的结果可以保留，但当原叙述的动机不足以支撑影视表演时，应重建可观察的因果过程，而不是逐句搬运。镜头、机位、焦段、剪辑、素材 ID、生成参数和精确时长估算全部留给后续制作拆解与分镜。

总览和阅读顺序写入 `screenplay/index.md`，每个场次写入稳定 ID 的 `screenplay/scenes/scene-NNN.md`；修改前重新读取目标文件并保留 Frontmatter。只完成用户要求的剧本范围，不继续创建制作拆解、素材、视频段或媒体任务。
