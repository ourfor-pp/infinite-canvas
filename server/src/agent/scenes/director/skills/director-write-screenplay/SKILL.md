# 分场剧本创作

先读 [标准分场剧本写作](references/screenplay-craft.md)，再读 `project.yaml`、`story/`、`direction/directing-rules.md`、`direction/visual-style.md` 与 `screenplay/`；需要核对外部来源时按任务检索 `sources/`。根据任务选择模式：

- 剧本为空或用户要求从故事重新创作时，以故事或已提供的外部原文为叙事来源、当前导演方案为改编依据；读取 `screenplay/index.md` 判断现状，不复述或恢复已经被用户要求替换的旧剧本正文。
- 用户要求修订现有剧本时，才读取现有剧本并在其基础上修改。

写作前承接导演方案的改编边界、人物矛盾、叙事视角、信息释放与情绪走向。方案缺失或只有视觉描述时，完整新写任务先使用 `director-design-style` 补齐必要的文字方向，不要求先生成风格板或重写来源故事；局部修订不以补齐整套方案为门槛。用户明确只要剧本时，在当前授权范围内作必要的内部改编判断并交付剧本，不擅自扩大文件修改范围。

把导演选择落实为场景中的行动、对白、反应与后果，不把方案条目复制进剧本。发现来源、方案或用户约束冲突时，区分可在场内修补的因果与需要改变核心动机、主题或结局的方向调整；后者说明具体冲突及建议，遵循用户已有授权，不能默默换掉核心解释。用户已授权统筹修订时同步更新相应导演规则，无需重复确认。

故事章节是文学叙事单位，不等于剧本场次。动笔前先在内部完成适配规划：依据导演方案和用户约束识别必须保留的事件、选择与后果，为各场分配与项目目标相称的表演容量，判断各场承担的叙事或体验作用及前后衔接；冲突戏检查行动如何引出反应并改变下一步，抒情或观察段落检查关系、感知或意象的积累，不强迫每场发生对抗或反转。规划只用于写作，不写入剧本正文。

直接写可阅读、可表演的分场剧本。动作只写观众能看见或听见的内容；对白、沉默、视线、反应和物理动作必须在正文中真实发生。每段对白使用独立的 Markdown 说话者标记：角色名单独一段并写成 `**角色名**`，台词放在紧随其后的普通段落；不得只靠单换行区分人名与台词。每场使用自然的场景标题和正文，不把节拍编号、逐段秒数、场景状态表或素材候选写进文档。

写入剧本文件前按写作参考的“提交前反证”检查信息效率、策略落实与结果依据，并对完整草稿执行以下内部提交检查：

1. 草稿遵守当前导演方案与用户保留项，叙事视角和信息释放一致；必要的方向变化已按授权同步，未把视听转化误作任意改写原作。
2. 动作段没有解释性心理、作者评价或替观众下结论的叙述。
3. 关键选择由此前行为和当场处境支撑，可行替代为何被放弃在正文中有依据；人物与观众的信息边界清楚，不能用方案里的动机说明代替现场因果。
4. 场内行动与回应相互影响，连续冲突没有换名重复；场间通过后果、期待、问题或有意的体验对照连接，而非只按事件顺序罗列。
5. 开场的观看理由与结尾的回报在正文中实际成立；各场为叙事、关系或体验提供具体作用，不用“营造氛围”解释无内容停留，也不机械删除安静段落。
6. 对白符合说话者在当场的目的与关系，对方回应影响交流；动作、对白和沉默按内容安排，避免复述已知信息与通用表情填充，总体表演容量适合项目目标。

任一项不满足时先重写草稿，不得仅在回复中宣称“已经递进”“因果完整”或“符合目标时长”。在改编边界和当前授权内删改冗余对白、动作或场景，保留必要的因果、关系与体验积累；原故事的结果可以保留，但当原叙述的动机不足以支撑影视表演时，应重建可观察的因果过程，而不是逐句搬运。镜头、机位、焦段、剪辑、素材 ID、生成参数和精确时长估算全部留给后续制作拆解与分镜。

`screenplay/` 在界面中是一份连续剧本，但文件工程按场次保存：总览和阅读顺序写入 `screenplay/index.md`，所有剧本正文写入稳定 ID 的 `screenplay/scenes/scene-NNN.md`，不得把场次正文同时复制到总览。修改前重新读取目标文件并保留 Frontmatter 的稳定 ID 和 `order`；场次增删或换序时同步更新总览。只写用户要求的剧本范围；用户仅要求剧本时交付正文，已授权后续制作时再组合制作拆解与分镜 Skill。媒体生成仍遵循用户的实际授权。
