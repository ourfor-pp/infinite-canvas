# 图片生成规范

使用当前会话引擎声明的图片能力与当前视觉风格；Codex 原生生图无需查询后台图片模型。再把适配当前模型的完整最终提示词写入目标 `prompt.md`；运行时必须原样提交正文，不会替 Agent 拼接风格、版式或禁止项。每次请求只生成当前明确的一张素材图片；提示词按当前模型的习惯清楚组织稳定身份、当前风格、目标媒体用途、输入图用途和通用禁止项，不堆叠重复同义词。真人皮肤和相机约束只用于 `live_action`；二维、三维、插画、手工和图形风格使用各自媒介约束。

角色基础设计固定为一次请求、一个结果、一张横版 16:9 三栏身份板。左栏是完整正面全身，中栏是完整背面全身，右栏是放大的正面头肩面部近景；三个面板必须呈现同一身份、同一体型、同一发型和同一基础服装，且只写入 `identity/primary.*`。这些要求连同浅色无内容背景、无文字、无标注和无额外人物必须直接写进 `prompt.md` 正文。不得请求或保存独立的 `face-closeup`、`body-front`、`body-back` 结果。真人角色是否使用风格图需要判断示例面貌污染风险；非真人媒介通常可显式引用统一风格板，但正文必须限定只继承媒介、线条或材质、色块、阴影和配色，不得继承示例人物身份。场景和道具可按当前风格需要显式引用统一风格板。

多图输入必须逐张声明用途并按身份、服装、风格、构图排序：项目内图片写入 `prompt.md` Frontmatter `references`，用户专属输入放同目录 `inputs/`，正文再按实际发送顺序说明每张图的作用。身份参考只锁定授权人物的面貌、年龄感、肤色和体型；服装参考只锁定轮廓、结构、材质与配色；风格参考只锁定媒介表达；构图参考只控制版式。不得混合不同图片中的人物身份。无身份参考时直接使用完整选角描述文生图。

提交前核对当前图片工具声明的参考数量上限，合计项目引用与用户输入；图片工具与 H3 视频的参考预算分别计算，不能沿用彼此限制。超限时按本段身份、关键道具和连续性需要选择参考，已有整板能够清楚提供的空间或普通道具信息可复用，不为了凑齐全部素材逐张附加。同步更新 Frontmatter、实际输入顺序和正文图号，不静默截断引用，也不删改剧情来适配数量。工程校验通过只证明文件契约有效，仍须检查实际工具参数。

项目内参考使用工程根相对路径，格式如下；`purpose` 只允许 `style_reference`、`identity_reference`、`wardrobe_reference`、`composition_reference` 或 `reference_input`：

```md
---
references:
  - path: direction/references/style-board.webp
    purpose: style_reference
    label: 统一视觉风格
---

这里开始就是原样发送给模型的完整提示词正文。
```

每次生成尝试使用唯一记录名称（目标 ID 加本次回合或尝试标识），写入前确认目标记录不存在；重做同一素材不得复用旧请求/结果记录名。保留该次实际提交提示、显式输入、工具调用 ID、输出路径和审阅结论，采用版本另行指向结果。发现历史记录缺失时只从已有权威事件或归档恢复，标明恢复来源和缺项，不根据当前提示反推旧请求。
