# 制作拆解规则

制作拆解是剧本与素材、分镜之间的结构化契约，不是另一份剧本。

- 场次 ID 在同一剧本结构内保持稳定，优先沿用正文场景编号。
- `heading` 保存正文中的完整场景标题；`title` 是便于浏览的短标题。
- `openingState` 与 `endingState` 描述人物、信息、关系或物理局面的变化。
- `dramaticTurn` 只写本场发生的关键转变，不写主题总结。
- `requiredDialogue` 只收录删掉会改变剧情、关系或信息的原句。
- `beats` 按表演顺序覆盖动作、对白、沉默和反应；一个节拍只承担一个清晰变化。
- 秒数是表演容量估算，应容纳真实动作与对白，不得反向删减剧本以凑目标时长。
- 人物和道具使用剧本名称，稳定资产 ID 在后续素材匹配阶段绑定。
- 不记录景别、机位、焦段、运镜、切镜、画格或模型参数。

## 结构诊断

- `duration`：可信表演时长明显偏离项目目标；说明偏差来自哪些场景，不用简单字数代替表演估时。
- `repetition`：相邻或连续场景重复相同的阻力、策略与结果，没有提高代价、改变信息或推动关系。
- `causality`：重大决定、态度转变或结果缺少正文中可观察的证据、压力与反应链。
- `scene_function`：删除某场后信息、选择、关系、风险和后果均无实质变化。
- `coverage`：原故事中影响因果、人物选择或结局的事件与后果没有进入剧本。

每个问题必须指向具体场次并给出不依赖题材的修订方向。不要把节奏偏好、角色是否讨喜、类型片惯例或个人审美本身判定为错误。

## 文件格式

`overview.md` Frontmatter 为 `id: screenplay-breakdown`、`kind: screenplay-breakdown`、`reviewIssues: []`（有问题时填写上述结构）；正文是总览。各 `scene-NNN.md` 的 Frontmatter 保存完整场次字段，参照 [完整场次样例](scene-example.md)，kind 固定为 screenplay-breakdown-scene，文件编号决定读取顺序。正文只写补充说明，字段不得只藏在正文中。服务端从这些文件更新制作拆解投影，segment.md 的来源指向这里的场次 ID 和 beats ID。
