# H3 视频段交接

以 `director_validate_video_segments` 的当前结果为准；本页描述创作与接口关系，不固定执行器配方。

- `capabilities.nativeState`：原生状态续接是否可用。为真且本段为 `continue` 时加载前段状态，隐藏重叠由后端管理；为假时按 `route` 使用参考音视频续接，不能称作确定性原生延展。
- `durationLimits`：当前段允许的计划时长。普通段和原生续接窗口可能不同，超限应按戏剧变化拆段。
- `nativeWindow`：预计新增帧数、隐藏重叠和实际输出秒数；时间线使用实际媒体时长，不能按计划秒数截掉对齐尾帧。
- `usesStoryboardStartGuide`：后端是否在整板之外附加首格引导。Agent 保持整张故事板，不手动裁格。
- `guideFraming`：实际提取首格的 `input` 尺寸、预览画幅 `target` 与在首格坐标中的中心裁切区域 `crop`。生成前检查该区域中的头部、手部、关键道具和表演空间，不能只看整板或未经画幅适配的首格。裁切比例不是质量门槛；必要时用原生整板编辑调整取景或留白，再按实际返回图复核，不拉伸人物、不自动加黑边、不静默取消引导。此字段不适用于原生续接和普通非时序参考图。实际只有首格作为时序引导；其他画格仍在整板参考中，不能把其模拟裁切当作真实末帧输入。根据镜头所需的可见动作审查，不把全程露出双脚或完整全身设为通用门槛。
- `referenceBudget.selected/omitted`：本次选用及省略的素材；有重要身份参考被省略时先修订本段引用。
- `acceleration` 与 `recipes`：当前选择的加速或基础配方及质量配置。以它们判断实际生成路径；不要仅凭声音策略标签推断步数或加速支持。

## 提交与结果

普通段提交整张故事板。只有独立视觉过渡使用已生成的前段尾帧与后段首帧。`qualityPreset` 为 `preview` 或 `final`，后者表示视频段质量，不代表已完成整片合成。

通常调用 `director_generate_video_segment({ segmentPath, qualityPreset })`，省略 `recipe` 让服务端按能力选择。普通图片参考 Ref2VA 在加速就绪时默认八步；独立音频参考默认基础配方，首尾帧也不套用此加速结论。需要排查加速造成的质量问题或用户要求基础版时，独立段显式传 `recipe: "base"`；保留原结果与问题记录，再比较重做。续接继承前段状态的配方，不从中途切换；需要基础版连续镜头时，从该镜头首段开始重做并依次生成后续段。不要改写状态身份来绕过校验。

生成工具读取工程文件；不提供数据库 ID 或 revision。只提交一次，再按任务 ID 查询状态。产物检查使用返回的工程路径或`videos/seg-<segmentId>/preview.mp4`、`final.mp4` 和 `model-audio.wav`（segmentId 为工程稳定 ID）；首尾帧通过视频取样获得。原生累计画面与原声由后端合成链处理，不自行拼接累计视频与重复段。

提示内容只展开已确定的动作与摄影，中文对白原文保留在唯一 `<d>` 来源。先修正预检阻断项，再按用户授权范围生成；接口校验通过不等于连续性和声音质量已经通过。


## 最终提示文件

`videos/seg-<segment.md中的id>/video-prompt.md` 是生成入口读取的最终提示正文，不附加 YAML Frontmatter、审阅说明或 Markdown 代码围栏。官方 Skill 的六段结构（首尾帧使用其对应格式）直接写进该文件；单独的 `h3-prompt.md` 不参与提交。空稿会阻断生成。画格、对白和导演文档仍用于规划与校验，正文由 Agent 根据这些权威内容编写，服务端不再补充创作语义。修改后重新预检，核对 `finalPrompt` 的路径和哈希；查看生成结果中的实际请求，不能以审阅稿代替提交证据。

普通 Ref2VA 的 `<Picture 1>` 是整张故事板，随后按预检 `referenceBudget.selected` 顺序对应角色、场景和道具。独立音频按 `segment.md` 的 `audioReferences` 顺序编号；仅在参考视频续接时，前段原声占 `<Audio 1>`。原生状态续接不把隐藏状态写成 `<Video 1>` 或 `<Audio 1>` 输入；首尾帧的 Picture 1/2 分别是前段实际尾帧和后段实际首帧。先查看实际素材，再按官方 Skill 定义主体身份和说话人；不要凭名称猜参考顺序。

原生续接的最终稿使用模型窗口时间：隐藏前缀长度为 `nativeWindow.overlapFrames / 24`，可见新内容为 `nativeWindow.outputSeconds`。先描述前缀延续，再把本段计划时刻t换算为 `overlapFrames / 24 + t * outputSeconds / 计划时长`；动作和对白时间一起换算。服务端只管理状态与输出裁切，不再修改正文中的时间。普通生成与首尾帧不套用这项偏移。

参考选择与剧情清单分开：`segment.md` 的 `references` 会转成额外模型图片输入，不能因为剧本提到一个普通物件就要求独立主图。若采用故事板已足够约束该物件，应实际看图后显式记录由整板提供视觉依据，在最终提示保留动作和物件特征；正常修订额外参考列表后重新审阅四文件绑定与预检。不可删除剧情、伪造参考、把需要身份锚点的缺失角色/关键道具静默略过，也不可仅为清除过期状态改哈希。
