# 视频提质

先查能力目录中的 `flashvsr-turbo-local` 和 `seedvr2-local`，只调用 available 的模型。应用模型引用分别为 `local-media::flashvsr-turbo-local`、`local-media::seedvr2-local`。

两者提供同一种组合处理：视频超分 → RIFE 补帧 → 原声音复用。`kind=video`、`mode=enhance`、`operation=enhance`、`prompt=""`，references 必须恰好包含一个 `kind=video, role=reference` 的源文件。普通上传视频也能处理，不要求 H3 latent；不接受创作提示词、生成时长、画幅或独立音频参考。

参数为 `resolution: "1080p" | "4k"`（分别以长边 1920、3840 等比输出）、`fps: "source" | 48 | 60`，可选 seed。默认 1080p、48FPS；原帧率达到目标时保留原帧率，选择 source 跳过补帧。输入限至少两帧、最长 15 秒、最高 60FPS、面积不超过 1920×1080 的恒定帧率视频。能力预检返回实际尺寸、帧数、帧率和时长，不推算或伪造结果。

服务内部采用带前后文的有限窗口，逐帧保持比例和编码；检测到切镜时隔离超分窗口并跳过跨镜头插值。自动切镜检测可能漏检，成片仍需观看。原音轨直接复制并核对解码音频哈希；不支持保留的音轨格式会明确失败，不静默转码。帧数对齐导致的时长误差不超过半个输出帧。

先完成创作与剪辑，再提质采用区间，减少重复计算。原片、裁切关系与提交快照由宿主保存；生成成功不自动进入导演时间线，不把提质输出用作 H3 原生续接状态。沿用统一校验、提交、查询、下载和 ACK 流程，不单列补帧模型，不暴露内部节点和内存参数。
