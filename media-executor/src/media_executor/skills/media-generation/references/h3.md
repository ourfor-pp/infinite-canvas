# H3 输入与提示

编写或重做提示前，通过 [官方指南入口](official-h3-prompt.md) 读取对应模式的完整原文与示例，再读 [动作与参考检查](h3-motion.md)。正文原样发送，不在参数中藏入人物档案、导演指令或工程状态。

按输入选择 `comfyui::minimax-h3-ref2va-local`（mode=ref2va）或 `comfyui::minimax-h3-fl2va-local`（mode=fl2va）。参考生成可不提供图片；有参考时显式登记 fileId、kind 和顺序。首尾帧使用 image 的 first-frame/last-frame role。时间锚点使用 frameIndex，视频锚点可用 includeAudio 控制声音。工程文件先通过 `media_import_reference` 登记，不传本机绝对路径或执行器路径。

使用 `media_validate_generation` 校验 kind=video、model、mode、operation=generate、prompt、references 和 params。params 使用 seconds、ratio、qualityPreset=preview/final，可显式指定 recipe=base 做基础配方对比。默认配方由执行器决定；不要自己拼图、选择采样器或计算隐藏重叠。实际帧数、时长、分辨率以返回 plan 为准。

续接使用 mode=ref2va、operation=extend，并传 continuation={generationId,fileId}，来源必须是已完成任务返回的 continuationStates。保持前段画幅和质量档，配方默认继承；不能用普通 mp4 代替原生状态，不自行改状态元数据。执行器核验哈希、模型与 VAE 身份、分辨率及允许的窗口。

结果区分 files（本次新增音视频）、cumulativeVideos（累计音视频）、continuationStates（双流状态），不要把累计文件当作新增片段。需要落盘时用 `media_save_result` 指定原扩展名的新相对路径。工程的任务绑定、镜头和时间线由对应领域工作流组织，不由本 Skill 创建。

生成完成后实际观看或取样检查画面身份、运动、切点和声音；工具成功只证明媒体生成与结构校验完成。

## 实际输入映射与声音边界

只定义本次实际使用的主体与媒体，不能把整片角色表复制到每段。图片、普通视频分别按各自提交顺序对应 `<Picture N>`、`<Video N>`，不能使用混合 references 数组的总序号。角色身份板是同一角色的多个视图，不是多人或目标分屏；故事板只提供其明确对应的镜头，不保留宫格和边框。来源看不清身份时补清晰图片，不能靠姓名猜测。

普通 Ref2VA 先按视频顺序为 includeAudio:true 的同步音轨分配 `<Audio N>`，跳过静音视频，再按独立音频顺序继续编号。例如视频 1 静音、视频 2 启用声音并另有独立音频，则视频 2 的声音为 `<Audio 1>`，独立音频为 `<Audio 2>`。图片、时间锚点和原生续接状态不占普通声音编号。声音的实际用途与说话主体按官方指南声明，不因文件有声就要求复制。

参考必须真正提交；提示提及的文件不会自动成为输入。`frameIndex` 表示执行器时间锚点，不是普通参考序号。独立音频通过 kind:audio 提交，音色或节奏参考不应夹带原音轨中未计划的对白。当前链路不承诺逐样本复制原声，需要精确复用时由调用方在后期明确合成并检查同步。

内容超出单次窗口时交回所属场景重新规划，不压缩对白、删停顿或增加未规划切镜。含对白、旁白或精确动作音时不要把 Turbo 原声当作验收结果；PDD 与 Turbo 是不同配方，记录实际 execution，而不是凭 qualityPreset 推断。预览和最终质量、配方与种子沿用用户选择；需要对比时显式说明变量，不擅自切换默认模型或批量重试。
