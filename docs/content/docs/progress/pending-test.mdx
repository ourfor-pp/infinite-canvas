# Pending Tests

The current release needs manual verification in these areas:

- Agent turn completion: after approving an operation, the final Assistant Markdown must remain visible both live and after refresh; the handled approval should move into the collapsed process history, and the temporary completion pill should disappear.
- Agent conversation and composer: verify grouped rounds, collapsible thinking/tool process, inline approvals and questions, stable streaming/history scroll, virtualization beyond 80 items, unread return-to-bottom, local error recovery, atomic Skill/canvas/asset/style mentions, IME-safe editing, structured copy/paste, attachment drag-and-drop, and per-session drafts.
- Agent complete-history recovery: after a refresh or service restart, a turn containing hundreds of streaming deltas must still restore its user bubble, process, and final answer without showing a non-functional “load earlier” control.
- Agent user-message actions: hovering or focusing a user bubble should reveal circular copy and restart controls. Restart must ask for confirmation, create a separate session truncated before that message, restore the original versioned composer document and attachments without auto-sending, and leave canvas/workspace files unchanged.
- Agent steer and persistent queue: direct messages start idle sessions, steer appends to the same SDK input stream, queued messages dispatch FIFO, idempotent retries never duplicate turns, waiting approvals reject steer but accept queue, restart/failure/cancel hold queued work for confirmation, and retry/send-now/delete preserve file references correctly.
- Agent Tool Search: Anthropic Messages providers should enable SDK Tool Search by default and show “搜索可用工具” in the conversation, while OpenAI-compatible/Ark proxy routes should disable it by default. `AGENT_ENABLE_TOOL_SEARCH=true|false|auto|auto:N` may override the default. Admin runs must expose the selected mode and call count; Skill `allowed-tools` may only merge registered non-destructive application tools and must never enable shell, internet, or deletion tools.
- Story creation and Markdown text nodes: ask Agent to write a story containing a title, several chapters, and an epilogue. The story Skill must create exactly one generic text node, render Markdown headings, paragraphs, emphasis, lists, quotes, links, and code in reading mode, and expose the original Markdown for editing on double-click. Continuing or revising the story must update that node instead of creating chapter cards.
- Semantic canvas ports: text, image, audio, visual-style, and creative-asset ports must reject incompatible links, enforce single/multiple input limits, preserve port IDs through save/copy/undo/Agent operations, and ignore old connections without port IDs.
- Visual-style orchestration: create template and custom styles, upload a reference image, set one project default, override it with an explicit style connection, remove a style node without deleting the entity, and permanently delete only through confirmation. Asset generation snapshots must retain the resolved style revision, description, reference file, connected text, and connected media.
- Content-first creative cards: names and descriptions auto-save after roughly 600 ms and flush before generation, collection, upload, or Agent handoff. Main and historical design-sheet clicks only preview; Delete/Backspace in the preview must not reach canvas shortcuts; changing the primary image must use the explicit star action and keep all variants.
- Agent handoff: “交给 Agent” on an asset or style opens the left project conversation, preserves the existing draft, inserts a removable reference chip, and does not send automatically. Sending must persist the asset/style reference and display the complete SSE thinking, tool, approval, error, and result flow in the same conversation.
- Creative business cards: create character, scene, and prop cards from “业务设定”. Each kind has one content-fitting fixed-size card with no empty lower section, compact/expanded modes, tab switching, double-click expansion, or layout jump. The card directly contains the complete landscape design sheet, name, status, description, reference uploads, prior versions, Agent instruction, and generation. It has no bottom action bar: Agent handoff and regeneration live in the top-right, while an empty design sheet generates directly from its centered action. Character cards additionally contain voice description, reference audio, sample line, and playback.
- Creative-node editing and generation: all three asset kinds should use one drawable `description` paragraph instead of fixed personality, relationship, backstory, owner, or narrative-purpose fields; characters additionally use `voiceDescription`. Unsaved semantic edits must save before generation without overwriting concurrently returned media.
- Creative-node deletion and library workflow: deleting one or several business cards must use the server-authoritative path once, must not show a false “updated in another page” conflict, and at most one real conflict dialog may exist per project. An already-collected library snapshot remains available, and reinserting it creates an independent business card rather than silently linking to its source project.
- Novel extraction: edit proposed names, inclusion, type, merged duplicates, complete visual descriptions, and character voices before confirming. Creation must be atomic, create independent cards without persistent Group nodes, and keep character descriptions free of personality/relationship/backstory, scenes free of people/events, and props free of ownership/narrative purpose.
- Design sheets and references: character output must be a 16:9 bust plus front/three-quarter/back four-panel sheet; scene output a main environment plus detail inset; prop output front/45-degree/detail views. Uploaded reference images or character audio must be passed only to capability-compatible models. A generated sheet becomes primary automatically while prior versions remain selectable through authenticated URLs.
- Project-scoped Canvas Agent: ordinary pages must have no Agent entry or mounted panel. Each canvas project must retain its own panel state, draft, selected session, history, attachments, and unread counters. Two sessions in one project may run concurrently; leaving the canvas must not cancel either run, and reopening or refreshing must recover every session from the project SSE summaries plus REST/event-sequence snapshots without gaps or duplicates.
- Agent identity and automatic permissions: verify users and projects cannot read one another's sessions, files, runs, references, project settings, or workspaces. Reads, queries, non-delete canvas edits, generation, workspace writes, publishing, selection, focus, and project navigation should run automatically. Node/connection/asset/creative-asset deletion and protected-setting changes must cover SDK auto allow, auto deny with a Chinese reason, and manual escalation. Manual escalation offers once/session/project scope, and project scope writes only narrow rules to the current project's `.claude/settings.local.json`. `ask_user` and novel-proposal confirmation must still wait for business input.
- Agent canvas tools and generation: verify revision-aware node creation/update/connect/delete, conflict handling, model discovery, persistent generation creation and polling, project/node task association, terminal result writeback, `project.updated` refresh, and `CLIENT_REQUIRED` for navigation/selection/focus when no page is active.
- Agent project workspace, attachments, artifacts, and Skills: all sessions in one project use `agent/users/<userHash>/projects/<projectHash>/`; attachments deduplicate by file ID, deleting a session preserves shared files, and deleting the project removes its file references and workspace. Same-path writes complete in order via atomic replacement while different paths run concurrently, and publishing waits for the relevant write. Skill source changes synchronize by content hash through atomic directory replacement into the project's `.claude/skills` without concurrent runs deleting each other's files.
- Agent storage upgrade: upgrade a storage/protocol v1 database with complete sessions, runs, and events. Startup must first create a database and old-Agent-directory backup with a SHA-256 manifest, clear legacy SDK session IDs, append an explicit context-reset event, preserve old session directories only in the backup, and move session file references to the project. Success, unknown versions, damaged manifests, conflicting backups, and interrupted retry must all be covered; no failure may overwrite the original database or old Agent directory.
- Agent provider compatibility: test direct Anthropic and New API Messages as well as OpenAI, OpenAI-compatible, and Ark models through the private protocol proxy, including streaming text, thinking/tool use, images, API Key/Auth Token, 429, timeout, cancellation, and sanitized failures. Gemini-native models must not be selectable for Agent.

- Administrator configuration: `/admin/ai` should use a three-level master-detail layout with configuration categories, a provider list, and one selected provider detail. It should contain providers, Agent, model/generation defaults, shared prompt sources, service backups, and runtime tasks. ComfyUI must appear in the provider list as a local workflow provider. Provider editing should use a compact centered modal with one shared column header and searchable model rows; every model binds a registered call scheme that derives output, input, request path, and Agent eligibility. Global defaults must initialize all users and clear automatically when their model becomes unavailable.
- Backend-only generation: text, image, video, audio, canvas, plugin-host, and Agent canvas generation must contact only the application API; browser traffic and ordinary responses must not expose provider endpoints, credentials, ComfyUI nodes, or temporary result URLs.
- Persistent task queue: verify global, per-user, and per-provider concurrency, cancellation, WebSocket text deltas, REST recovery after reconnect, continued work after closing the page, safe remote-task recovery after restart, and `SERVICE_RESTART_INTERRUPTED` for non-recoverable one-shot requests.
- Database upgrade: restart an existing v0.17 development database whose generation table predates `error_code`; startup should add the missing column automatically, retain queued tasks, and keep the Express and WebSocket services online.
- Provider adapters: verify each registered text, image, video, and audio call scheme against OpenAI, OpenAI-compatible, Anthropic, Gemini, Ark, and all fixed ComfyUI workflows. The selected model scheme—not the provider preset—must decide the generation adapter, request path, input validation, and Agent support. Also verify Anthropic system prompts, conversations, streaming, image input, API keys, auth tokens, and custom base URLs; a New API domain root should normalize to `/v1`, discover models through `/v1/models`, and generate through `/v1/messages`.
- Settings and security: v3 preference import/export must exclude providers, credentials, and scripts; model capability and reference ownership checks must reject invalid work, public model responses must contain display metadata only, and the administrator task list must hide prompts, content, and sensitive error details.
- Backend development chain: `./dev.sh` should reuse or start ComfyUI on `127.0.0.1:8189`, Express on `127.0.0.1:3001`, and Vite on `0.0.0.0:3000`; ordinary-user page responses must not expose the ComfyUI address.
- Server data and isolation: two browsers using the development user should share projects, assets, records, and settings; simulated fnOS users must remain isolated, and concurrent canvas edits must produce a revision conflict with reload or explicit overwrite choices.
- Legacy import: an empty backend should offer a one-time IndexedDB import, preserve old data after upload or transaction failures, become idempotent after success, and read only server data after refresh.
- Backend ComfyUI tasks: all four fixed workflows should continue after the page closes, recover status and results through REST/WebSocket, and report cancellation, node errors, offline nodes, timeouts, and restart recovery clearly.
- Admin backups: administrators should create, list, validate, and restore complete WebDAV snapshots, including AI service configuration, without replacing current data when a manifest, hash, or SQLite integrity check fails.
- File service: authenticated image/audio/video URLs and byte ranges should work, while traversal and cross-user access are rejected and orphaned files are cleaned only after the grace period.
- Canvas navigation: left-clicking a node should select it and dragging should move it; left-clicking blank canvas space should deselect the current node and close its toolbar/prompt panel, while dragging blank space should pan immediately without Control. Shift + background drag should draw the multi-selection range with visually stable dashes at every zoom level. The Move tool, middle-button drag, and Space + drag should still pan from either the background or a node; Ctrl/Cmd/Shift + node click should remain additive selection, and Space must remain available inside text inputs and editable content.
- Text-node scrolling: when a selected text node has overflow, the mouse wheel over its reading or editing area should scroll the text instead of zooming the canvas; moving the pointer outside the node should restore canvas zoom.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration.
- Canvas side panels: the Agent panel should occupy the left side and resize from its right edge, while Canvas/Assets/Prompt Library should occupy the right side and resize from its left edge; creative settings are edited from their canvas nodes and must not reappear as a separate right-panel tab. The top-left control should toggle Agent, the top-right “Resources” control should toggle the resource panel, and both entrance/exit animations should originate from their corresponding edges. The canvas top bar should no longer show Agent connection status, Documentation, version, or GitHub entries. The centered canvas toolbar must use the remaining canvas width without retaining the former left-panel offset. Clicking an element row should still smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; clicking the control should hide the floating toolbar and expand the slots upward and to the right. Every completed secondary image should keep a clearly legible primary-image action visible in both themes, and clicking the empty canvas should collapse the group.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.
- Multi-image resize: starting a resize while child images are expanded should collapse the group once, then resize the root node normally without triggering nested React updates or an application error.
- Multi-image alternatives: expanded images should use up to four columns so larger batches stay compact; every completed image, including the primary image, should provide an independent download action, while alternatives should also keep clearly legible create-copy and set-primary actions in both themes. Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- User configuration removal: the top navigation and router must no longer expose a user settings page or modal. Missing models should tell ordinary users that an administrator must configure them, while administrators are directed to administrator configuration. Configuration-file import/export and browser local-storage statistics should no longer be present.
