## 启用与登录

当前支持 Linux 本机，需安装 Bubblewrap 和 Codex CLI；不限制 CLI 版本号，使用实际协议握手与隔离验证判断可用性。管理员在「AI 配置 → Agent → Codex」配置 `/usr` 下的程序路径，进行设备码登录、连接测试后启用；模型留空使用 Codex 默认模型。账号保存于数据目录的 `agent/codex`，不读取或修改用户全局 Codex 配置。

导演侧栏新建会话时选择 Codex；会话引擎固定，历史可查看和续聊，暂不支持消息分叉。修改配置或退出账号前，需要结束当前 Codex 任务。

## 图片与其他媒体

Codex 会话直接使用原生图片生成与编辑能力，不使用管理员图片渠道。素材 MCP 只保留声音生成，故事板和风格板的 MCP 生图入口不向 Codex 暴露。视频、音频、媒体理解及成片继续使用现有导演工具。

原生图片在当前作品的 `.cache/codex-images` 中缓存，该目录在隔离进程内映射为 `/codex-home/generated_images`，不与其他作品共用。生成状态与图片预览进入当前回合；原生图片不会伪造管理员渠道的生成任务 ID。

Agent 读取工作区提示词和显式参考图，生成前后核对提示词哈希，然后按工程约定复制结果：角色 `identity/primary.png`，场景和道具 `design/primary.png`，变体目录 `primary.png`，视频段目录 `storyboard.png`，风格板 `direction/references/style-board.png`。已有文件索引负责媒体登记与页面刷新，认证和缓存不进入工程导出。

## 运行与恢复

每个活跃 Codex 会话启动独立 app-server，作品映射为 `/workspace`；系统程序只读，命令不能读取账号认证目录。网络复用宿主网络与代理，不额外限制私网或修改 DNS。

同作品的两种 Agent 串行执行。SQLite 是消息权威源；刷新和续聊恢复已有 thread，不自动重放生成任务。子进程退出或服务重启会保留历史并将当前回合标为中断，原生 thread 缺失时需要新建会话。数据库结构升级前自动备份。

输入框始终允许编辑草稿，引擎不可用只限制发送并独立展示原因。失效的管理连接自动关闭并重建；启动或 thread/resume 阶段连接退出最多重试一次，保留原 thread ID。任务已经提交后发生断线，不自动重复提交原请求；下次继续会恢复同一 thread。版本升级不清空账号或历史。
