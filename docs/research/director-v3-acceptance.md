# 导演 v3：三维预演实施与验收

本版将分镜工作区改为“一项一段戏”：场景共享空间与身份，每段包含多个机位、基础表演和明确起始状态。工程文件是创作权威源，SQLite 只维护索引与执行状态。旧 v1/v2 工程不转换、不支持导入。

## 工程与输入契约

- `scenes/<场景>/scene.json`：固定版本声明式空间、对象与素材绑定。
- `scenes/<场景>/segments/<段>/segment.md`：文字设计、时间预算和显式 `previsMode: skip`。
- 同目录 `previs.json`：唯一动作、轨迹、附着、对白与摄影时间定义；每段起始状态独立保存。
- `look-frames/<ID>/`：可选时间绑定图片、`frame.json`、显式参考和最终 `prompt.md`；`inputs/capture.json` 校验提取请求、预演版本、时刻及截图内容哈希。重新提取不更新旧主图的来源版本。
- `productions/<任务>/task.md`：`segmentRanges` 明确覆盖范围，`videoReferences` 明确用途和默认静音；图片按显式 `referenceImages` 顺序提交。
- 生成提交将媒体、预演数据和最终提示复制到任务 `runs/<生成ID>/`；采用的视频展示该次实际快照。上游变化标记待检查，失败保留旧视频。
- `timeline/timeline.json`：独立选片，允许同来源重复裁切与独立声音编排；不以预演计划切点冒充生成视频实际切点。

不存在独立整板生产、画格热点或图片确认门槛。图片缺失不阻塞预演；默认预演必需，跳过必须显式声明。Codex 使用原生生图；内置 Agent 使用已配置图片渠道，两者共享定妆帧工程约定。

## 运行依赖与边界

服务端固定 Three.js、Playwright 与 esbuild 版本。发布机需要 Node.js、FFmpeg、Playwright Chromium 和对应系统库；执行 `npm ci` 后运行 `npm run previs:install` 安装 Chromium，使用 `npm run previs:check` 验证实际启动与 FFmpeg。导出以独立工作进程启动 Chromium，使用同一求值与渲染代码逐帧生成 24 fps 静音视频，默认短边 480，继承项目画幅。并发 1，持久队列支持取消、失败重试与重启恢复，不要求用户保持页面打开。

人形、拟人动物、四足粗模和基础几何用于调度判断，支持走、跑、转身、看向、抬手、指向、持物、递物和简单接触。附着与交接时刻显式定义；不使用物理模拟推导剧情，不承诺复杂动作复刻。不支持的数据返回诊断。

Docker 静态资源和完整生产容器路径仍属于后续部署工作，不能据本地依赖检查宣称部署完成。
