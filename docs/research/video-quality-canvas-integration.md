# 画布视频提质接入

视频节点沿用现有模型选择器，分组显示「视频生成」「视频提质」。提质组只有 FlashVSR Turbo、SeedVR2 两个模型，RIFE 包含在各自的内部流水线中，不新增独立入口或补帧模型。

## 输入与行为

- 目标分辨率为 1080p、4K，按源比例分别以长边 1920、3840 输出，取偶数尺寸，必要时增加极薄留边；不是强制拉伸成 1920×1080 或 3840×2160。
- 目标帧率为保持原帧率、48FPS、60FPS，默认 1080p、48FPS；源帧率达到目标时跳过补帧。帧数按原时长对齐，误差不超过半个输出帧。
- 源输入限一个恒定帧率视频，至少两帧、最长 15 秒、最高 60FPS、像素面积不超过 1920×1080。校验实际逐帧时间戳，不能只按容器标称帧率判断。
- 有外部视频连线时使用外部视频，否则明确显示当前节点视频为待处理源；多条外部视频报错，不静默选择第一条。提质不使用旧创作提示词、图片或独立音频参考，普通生成仍沿用外部参考规则。
- 成功回填同一节点，失败或取消保留原视频。当前模型、目标分辨率和帧率是下一次处理参数；实际执行计划与输入文件由服务端生成记录保存。

## 执行边界

应用引用为 `local-media::flashvsr-turbo-local`、`local-media::seedvr2-local`。中立请求使用 `mode=enhance`、`operation=enhance`、空 prompt、一个视频 reference，以及 `resolution`、`fps` 参数；能力查询、校验、持久任务、GPU 调度、下载、哈希核对和 ACK 均沿用原入口。

正式扩展为 `media-executor/comfy-video-quality/`，安装到同一个受管 ComfyUI；没有新增服务或端口。内部顺序为超分 → RIFE → 编码与原音轨复制。每个核心窗口最多 41 帧、两侧各保留最多 4 帧上下文，逐帧保持比例和编码，不再整批创建高分缩放副本或完整补帧张量。源 RGB 暂存文件用 mmap 访问，任务退出后删除；检测到切镜时隔离超分窗口并跳过跨镜头插值。自动切镜检测不是完备的镜头识别，仍需观看。

Flash 使用已测过的 Turbo 五层 KV 卸载、FFN 分块和串行解码配方；Seed 使用 3B 转换权重、分块 VAE 和时序重叠配方。两个模型都可能重建纹理，不承诺无损细节恢复。原音轨直接复制并比较解码 PCM 哈希；无法保留的音轨格式明确失败，不静默重编码。

## 安装与来源

使用执行器 Python 运行 `scripts/install-video-quality.py --evaluation-root <已校验评测目录> --comfy-root <当前受管 ComfyUI> --data-dir <执行器数据目录>`。先设置 maintenance，等待任务、代理提交和 Comfy 队列排空；安装器再次检查持久队列，校验固定源码、Flash 解码器补丁、官方上下文张量和全部权重 SHA256，把依赖与源码复制到稳定运行时目录，不下载或替换权重。权重继续复用 SSD 上的 `VideoQualityEvaluation` 稳定入口。

固定源码为 Flash Comfy `153cf03343a116c85aee40d291125921cc33935a`、Seed Comfy `4490bd1f482e026674543386bb2a4d176da245b9`。Flash 权重来自官方 `ruchangyao/FlashVSR_plus` 的 `46b79520946ac67dec94d1566490690953c7debc`；RIFE 来自官方 Comfy-Org 同仓。Seed 沿用此前记录的 Comfy-Org FP16 转换权重，仅删除 conditioning 张量以适配固定节点，未重新量化模型。完整上游来源及转换记录见此前[本机评测](h3-video-quality-local-evaluation.md)和 `.tmp/h3-4k-evaluation/` 来源清单。

稳定运行时为 `~/.local/share/infinite-media-executor/video-quality/`，`runtime.json` 保存已核对文件的摘要、尺寸和文件状态，`provenance/` 保留原始来源清单、转换记录与补丁。健康查询只检查文件状态，不在高频查询中重复全量哈希。维护时用 `scripts/qualify-video-quality.py` 经统一调度执行真实推理、下载与 ACK；失败保留证据，不能凭节点存在或 HTTP 200 宣称验收通过。
