# 导演台统一实时同步版本方案

状态：已实施并完成本地自动化与独立浏览器验收，等待用户实际项目确认。作为独立功能版本验收；版本号在正式发版时确定，本方案不修改 VERSION、不执行发版流程。

## 目标与边界

导演项目的业务数据被页面、Agent、生成任务或外部文件操作修改后，所有相关页面、详情、预览和状态自动反映最新内容，无需整页刷新。实时同步保持当前编辑草稿、选中项、滚动位置和播放状态；不因事件触发自动生成或付费操作。

“全部接入”指所有读取项目权威业务数据的位置，包括未打开页面的缓存失效；不要求每个组件建立连接，也不在每次变更后重新请求整个项目。Agent 对话继续使用独立的会话 SSE、runId 与 eventSeq 协议，本版只统一项目业务数据的更新，不合并对话协议。

## 实施前的代码事实

- `server/src/director-workspace.ts` 已有递归文件监测、250ms 合并、哈希索引和文件到数据库的同步；`indexDirectorProject()` 检测变化后已调用 `emitWorkspaceUpdate()`。
- `server/src/index.ts` 已把该通知转换成 `director.updated / file-workspace`，通过现有 `/api/events` WebSocket 推送。不是缺少文件监测或缺少整条通用事件。
- `web/src/components/layout/server-bootstrap-gate.tsx` 转发事件；`web/src/pages/director/project.tsx` 对 `director-updated` 只调用 `loadState()`。素材和风格另外监听自己的实体事件，因此文件监测路径未贯通这些独立数据源。
- 素材详情、逻辑文档、校验、预检、播放计划等还有独立请求和刷新依赖；成片列表仍每两秒轮询。
- 素材 URL 使用实体 revision，但同路径文件覆盖时 fileId 不变，媒体内容哈希未直接参与素材版本判断；只依赖文件 birthtime 不能保证缓存失效。
- WebSocket 当前断线后重连，但没有为导演项目统一执行重连快照对账；`loadState()` 也没有防止较旧请求晚返回覆盖新状态。

以上为本次完整追踪对上一轮诊断的修正。孙悟空重绘已写入主图并更新数据库，页面刷新缺口集中在事件消费及独立数据源同步。

## 统一事件与权威快照

复用当前已鉴权的 WebSocket，由服务端按用户隔离、按 projectId 归属。业务写入成功或文件同步完成后再发事件，统一使用有界的失效通知，不广播大正文、图片内容、整棵项目状态或绝对文件路径。

当前事件字段：

```ts
type DirectorProjectChanged = {
  type: 'director.project.changed';
  projectId: string;
  version: number; // 项目内持久、单调递增的同步版本，独立于实体 revision
  changes: Array<{
    resource: 'project' | 'sources' | 'story' | 'script' | 'direction'
      | 'assets' | 'segments' | 'timeline' | 'generations' | 'renders' | 'validation' | 'media';
  }>;
};
```

- 事件表达“哪些资源需要更新”，API 快照负责提供最新业务内容、实体 revision 和媒体 contentVersion。同步版本和业务编辑冲突版本分开。
- 单项目事件合并去重；ID 过多时提升为资源级失效，无法可靠映射时提升为项目级失效。连续写文件期间合并，写入持续很久也设最大等待时间，避免无限推迟通知。
- 一次业务操作涉及的数据库投影完成并提交后，推进同步版本并发布一次通知；避免 API 写入、文件监测和生成回调重复广播同一变化。
- 文件仍在写入或校验失败时，保持最后一个有效业务快照，发布校验状态；重试成功后再发布业务变化。无效文件不可静默覆盖有效对象，也不能因只更新了文件索引而永久漏掉后续业务通知。
- 项目删除、资源删除/重命名、批量变化、生成状态和成片完成均进入同一失效入口。进度事件独立限频，不对每个进度 tick 全量读取项目。
- 初始化、重连、标签页恢复时对当前项目执行权威快照对账；事件有版本缺口时执行受影响项目的重新校验。首版不新增持久事件重放系统。
- 请求期间先记录事件；快照带同步版本，完成后继续处理更新版本的失效项。切换项目后旧响应不得写入当前视图。服务端重启后同步版本不能回退。

## 前端接入规则

由全局事件连接调用导演项目同步入口，统一维护资源失效、请求合并和版本校验。沿用当前 Zustand 与 API 结构，不引入新的状态管理框架。

1. 项目共享数据和动作收敛到统一 store/hook；移除页面中重复维护的素材、风格、任务副本。全局数据不继续通过多层 props 转发。
2. 活跃页面及已打开详情刷新受影响查询；未打开页面只标记失效，进入时加载。一个查询同时最多一个请求，期间的新变化合并为一次后续刷新。
3. 旧请求不能覆盖较新结果；重复事件、乱序事件、跨项目事件不得产生状态回退或错误关联。
4. 更新列表保持筛选、排序、滚动与仍存在的选中项。对象删除后清除失效引用，关闭无法继续操作的详情并给出一次明确提示。
5. 文档无本地改动时更新阅读内容；存在本地改动时保留草稿并提示外部更新，保存使用原版本校验，禁止默默覆盖任一侧内容。
6. 图片、音频、视频及下载引用统一使用文件内容版本；同路径覆盖也产生新 URL。只有受影响媒体换源，无关事件不重置播放器。
7. 正在播放的媒体被替换时提示新版本，切换或下一次播放采用新源；普通时间线/任务状态变化保留当前播放位置。当前媒体被删除时停止播放并提示。
8. 网络中断保留当前可读内容；恢复后自动对账，失败显示可重试状态，禁止持续堆叠错误提示。任务列表事件与恢复路径验收通过后移除固定轮询。

## 实施批次

### A：统一基础链路

定义协议、资源映射、同步版本和媒体内容版本；连接文件监测、API 写入、生成/渲染回调。实现全局消费、请求合并和重连对账。先以“同路径替换角色主图，列表及已打开详情自动更新”证明完整闭环。

### B：全部工作区接入

按覆盖清单接入文档、导演方案、素材、分镜、视频创作台及跨页面区域。同步处理删除、派生依赖失效、草稿冲突和播放器换源规则，移除确认不再需要的重复监听及轮询。

### C：故障与端到端验收

验证批量写入、无效中间文件、乱序/重复通知、请求竞态、跨项目切换、多标签页、断线和服务端重启。完成覆盖矩阵后作为一个版本交付，不把仅修好素材页视为全版本完成。

## 验收标准

- 文件稳定且业务同步成功后，本地环境活跃页面更新目标不超过 1 秒；分别记录监测、同步、事件传输、API 和 DOM 更新时间，超标能定位阶段。
- 从 Agent 文件写入、页面保存、生成完成、外部文件修改四种入口验证；事件本身不触发任何媒体生成。优先使用隔离项目和现成媒体替换，付费生成沿用已有明确授权。
- 新增、修改、删除和重命名均能更新关联列表、详情、预览和引用；故事板始终按整张媒体显示。
- 原地覆盖同路径、相同大小且保留时间戳的图片仍更新内容版本，不依赖文件名、文件大小或 birthtime 猜测变化。
- 未保存故事/剧本/导演方案草稿不丢；无关资源更新不重置选择、阅读位置或播放进度。
- 断线期间发生变化，恢复后无需刷新页面即与权威快照一致；重复和乱序事件不回退，旧项目响应不串入新项目。
- 连续 100 次文件变动不会产生对应数量的全项目请求；记录合并后的事件数及查询次数，确保请求数按受影响资源受控。
- 覆盖矩阵每一行都有自动化或浏览器验收记录；必要类型检查、回归和构建通过。浏览器验证使用独立测试页面，不关闭用户已有页面。

## 实施与验收记录

- 服务端以 `director-sync.ts` 统一合并通知，SQLite `director_sync_versions` 持久保存同步版本；`GET /director/projects/:id/sync` 返回指定资源的权威投影。生成进度只读取当前项目任务，不扫描整个工程。
- 文件监听改用固定版本 Chokidar 4.0.3，处理连续原子替换，并使用原始通知加内容哈希检测同大小、保留时间戳的覆盖。250ms 合并、750ms 最大等待和有界重试；索引先更新时记录 `needs_reconcile`，避免吞掉尚未投影的文件变更。
- 无效中间文件保留最后有效投影；合法删除反映到业务列表，缺失依赖保留为校验诊断，时间线不可用媒体从读投影移除，不重写创作文件。文件内容哈希进入媒体 URL 和 ETag。
- 前端 `DirectorSync` 合并资源失效、串行读取与版本校验；共享 store 保存项目快照，React Query 合并详情、逻辑文档、播放计划和预检请求。页面恢复、联网和 WebSocket 重连重新对账；移除成片列表固定轮询。
- 现有复制、重发、编辑、生成、下载和预览等操作继续保留。未保存文档保护草稿；素材详情、图片预览和 Agent 引用同步更新名称与删除状态；播放中同一媒体延期换源，暂停后采用新版本。
