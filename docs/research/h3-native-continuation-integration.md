# 原生续接接入边界

当前导演连续段仍在 `server/src/director-render.ts` 提取前段最后 22 帧视频与音轨，作为普通续接参考传入。这不等同于隔离实验中的原生双流 latent 尾引导与累计追加，不能据此宣称应用已实现无缝长视频。普通非连续 Ref2VA 段已接入故事板第一画格时间锚点；该约束不会用于连续段，也没有替代整板参考。

## 已验证的状态原型

`media-executor/experiments/h3-state/` 使用 safetensors 分别保存视频和音频张量，校验模型、VAE、来源、分辨率、帧数和 fps，加载后重建 ComfyUI NestedTensor。九项 CPU 回归覆盖精确往返、禁止覆盖、元数据不匹配、帧数与音频长度、非有限值、未知版本和截断文件。隔离节点还验证了输入路径与软链接越界拒绝。

固定版本 ComfyUI 的 SaveLatent 会对双流 NestedTensor 调用不存在的 `.contiguous()`；真实 CPU 对象已复现这一错误，因此没有直接沿用该节点或 pickle 对象反序列化。

真实 243 帧状态保存为 28,637,136 字节，经 HTTP 取回与上传、停止原进程并启动新进程后，独立任务重解码成功。全部视频帧 framemd5 和完整音频 PCM SHA256 与原输出一致，观测耗时 36.442 秒（Comfy 执行 34.909 秒）。

另一独立任务加载该状态并追加 119 帧，累计 362 帧；原视频和音频 latent 前缀逐元素完全一致，观测耗时 190.340 秒（Comfy 执行 189.117 秒）。唯一新增接点为第 243 帧，即 10.125 秒；接点相邻六帧未见明显人物或机位重置。完整运动、口型和听感尚未验收。

可核对证据位于 `media-executor/examples/h3-evaluation/liudeng/` 的状态重解码及前缀比较记录；原始视频、状态和任务报告保存在 `.tmp/h3-evaluation/liudeng/c-state-redecode/` 与 `c-state-continued/`。

## 正式接入仍需完成

- 应用以用户、项目、来源生成和模型版本维护状态归属；浏览器不得提交执行器本地路径。源视频替换后旧状态不得继续冒充当前状态。
- 执行器返回媒体输出与状态输出时应分开处理。应用现已将 h3_states 保存至独立 continuationStates，31 项 HTTP/SQLite 回归确认媒体分离、生成文件引用及跨用户读取拒绝；真实状态与来源视频、工程版本绑定仍待完成。
- 生成失败时保留可用的前段与状态；模型、量化、VAE 或分辨率不匹配时明确拒绝，不得静默降为普通参考并继续称为原生续接。
- 同时提供本段新增音视频与可继续的累计状态；时间线不得重复加入旧段或 22 帧隐藏重叠。
- 经真实导演入口验证两次独立任务、进程重启恢复、跨用户拒绝、源替换失效及完整片段视听效果后，才能将正式能力标记为已验收。

原型目前仅安装在隔离运行时，正式 ComfyUI 尚未安装状态节点。

新增 H3NewAVSegment 隔离节点从累计解码结果中提取新增画面与音轨。真实 362 帧视频为 15.083333 秒，而 40 Hz 音频 latent 对应音轨为 15.075 秒；模块仅补齐半个音频 latent tick 内的尾部量化差，超出差异直接拒绝，防止静默掩盖音视频错位。CPU 测试验证第 243 帧起取 119 帧、从第 324000 个 32 kHz 音频采样点起取原样波形，并补齐末尾 267 个采样点。真实隔离节点已完成：从 362 帧累计状态只输出 119 帧新增片段，视频 4.958333 秒、音轨 4.959 秒，未将前 243 帧重复输出。与对应累计编码视频尾段 SSIM 为 0.986610，不能声称重编码逐像素相同。完整视听和正式入口仍待验收。


## 导演来源绑定与原生媒体时长

`server/src/h3-continuation.ts` 已提供来源绑定和读取校验；导演结果写回在收到内部 `__h3StateContext` 计划与唯一状态输出时记录项目、视频段、生成记录、模型/VAE/帧结构及视频和状态 SHA256。读取时核对当前采用的视频内容、来源生成及其状态输出，拒绝跨用户/项目、模型变化、来源替换、状态内容变化和过期视频。项目工程中的完全相同媒体镜像可以具有不同文件 ID，仍以同一内容哈希和生成归属校验。

导演异步媒体处理在开始及写回前检查当前生成 ID，按最新 payload 合并并以 revision 条件写入，防止旧任务覆盖新任务或用户编辑。原生状态输出先经 ffprobe 检查实际画幅、24 fps、新增帧数和音轨；保存对齐后的 `videoDurationSeconds`，保留创作计划的 `durationSeconds`。服务端合成与原生音轨定位采用实际媒体时长，避免按请求秒数裁掉状态对应尾帧。

五十项相关回归通过，其中包含实际 FFmpeg、SQLite 来源绑定、处理期间编辑、旧任务拒绝及工程镜像重建。另使用真实 H3 新增 119 帧输出验证正式校验器，正确接受 362−243 帧并拒绝错误帧数/来源帧格，证据为 `media-executor/examples/h3-evaluation/liudeng/director-native-output-validation.json`。

生成入口已接入内部状态计划与来源校验，受实际执行器身份探测控制；正式节点安装、完整入口两次真实生成、状态导出/导入与界面实际时长展示仍需完成。当前正式运行时未安装状态节点，不表示用户已能在正式导演台发起原生续接。

## 完整导演 HTTP 入口两任务实测

Comfy 执行耗时分别为 72.206 与 108.022 秒，合计 180.228 秒；这不是冷暖状态控制的加速对照。首段视频 latent `[1,24,37,30,54]` 在续段 `[1,24,72,30,54]` 中的前缀完全一致，音频 `[1,32,2,207]` 在 `[1,32,2,405]` 中的前缀也完全一致。最终发送提示按官方 Skill 六段结构保存，报告包含实际运行图、任务 ID、来源绑定及 ffprobe 信息，见 `media-executor/examples/h3-evaluation/liudeng/director-native-api-report.json`。

完整链路正向验证已取得真实证据，但合格成片时长仍记 0。抽帧保持单一室内画面，尚未完成完整运动和听感验收；首段提示将台灯描述为左侧，与参考板实际右侧不一致，需要修正后再用于成片对照。此测试仅约 10.125 秒，同一入口跨越 15 秒、进程重启恢复、界面实际时长、工程导出和正式节点部署仍未完成。审片视频为 `.tmp/h3-evaluation/director-native-api/two-segments.mp4`。

接点六帧检查发现轻微姿态/构图变化：第 124 帧接点的 432×240 RGB 平均绝对帧差为 2.30257，临近帧约 0.12–0.40，整段中位数 0.48385，接点为最大值。该指标不能单独证明视觉破绽，但与抽帧观察一致，因此暂不接受“无缝”结论。下一步需把同一累计状态一次性解码，对比其接点与独立首段尾帧，以区分生成连续性和 VAE 分段末端上下文差异。


## 解码边界定位与成片路径修订

同一份 243 帧累计状态独立解码耗时 20.993 秒。随后同一任务分别将首段 124 帧状态与累计 243 帧状态解码为原生 864×480 无损 PNG，排除 H.264 和导演转码差异。结果为首段前 120 帧逐像素相同，只有索引 120–123 的最后四帧发生变化。累计解码接点 RGB 平均帧差为 1.51442，而旧首段尾帧与累计新增首帧直接相接为 2.19888。数值不等于完整视听验收，但确认旧首段解码尾部不能视为追加后的最终画面。

固定 ComfyUI `40c4fcdf513a4523e39d54a9d391908af8df8171` 的 `comfy/ldm/minimax/vae.py` 在 `decode_temporal` 中混合相邻解码块；到末块时直接输出剩余 overlap。追加 latent 后出现后继块，末尾画面因此改变，即使原 latent 完全没变。真实任务、无损帧差和编码对照见 `media-executor/examples/h3-evaluation/liudeng/director-native-decoder-boundary.json`。

据此修订落地方案：保留各段来源视频与状态归属，同时单独保存原生连续链的累计音视频输出；预览/最终成片对连续链采用最新有效累计解码，不再将旧预览的尾部当作稳定片段直接拼接。需在合成前验证整条来源链、实际帧数和视频段顺序，不能为了接点修补静默改写来源视频及哈希。当前代码仍仅返回新增段，此方案尚待实现，并需检查音频解码末端是否有同类上下文变化。

社区节点作者也明确保留语义接点不保证无缝的边界，并建议对追加后的累计 latent 解码，参见 [作者 README](https://github.com/ttulttul/ComfyUI-Minimax-H3-Continuation#limitations)。这支持保留累计成片路径，但不能替代本地接点和完整听感验收。


## 累计媒体输出契约与音频对照

原生工作流新增专用输出节点 ID `h3_cumulative`，使用现有 H3 音视频裁取、CreateVideo 和 SaveVideo 节点保存完整累计结果，不新增运行时插件。普通 `files` 只保留新增段，累计视频下载至独立 `cumulativeVideos`，状态保留在 `continuationStates`；均沿用生成记录文件引用和用户文件权限。真实同一解码任务返回 119 帧、4.958333 秒新增段和 243 帧、10.125 秒累计音视频。9 项相关回归、新增下载/鉴权/文件引用检查及服务端类型检查通过。证据为 `director-native-cumulative-output.json`。导演来源绑定、连续链预览和合成尚未消费累计媒体，不能将本项输出契约验证宣称为完整修复。

音频使用 SaveAudio 无损 FLAC 对照父段与累计状态解码，32 kHz 双声道父段 165600 个采样点、累计 324000 个采样点。原段范围的最大绝对差为 0.00088501，差值 RMS 约 0.00003135；微小差异分布于多处，并非已经证实只影响末尾。该测试排除了 AAC 编码，但仍包含解码计算及 FLAC 量化差异，不足以证明可听见的破绽或声音无缝，需要完整听感与接点波形验收。


## 累计媒体来源绑定

导演写回现要求原生生成包含唯一累计视频，先校验完整累计帧数、24 fps、画幅与音轨，再保存累计视频文件 ID、内容 SHA256、生成 ID、状态 SHA256 和累计帧数至 `h3CumulativeVideo`。普通新增段和原状态不被改写；后续非原生生成清除旧累计绑定。读取累计视频时复核当前采用视频、状态、生成结果中的累计文件及其哈希，再沿权威生成请求中的前段快照追溯来源链，拒绝跨项目、循环、帧数不递减、前段已替换或校验期间任一段发生变化。

真实 FFmpeg/SQLite 回归覆盖初始累计绑定、文件引用、跨用户拒绝、错误累计帧元数据、内容篡改和循环来源链拒绝。预览和最终合成仍未消费该解析结果，多段真实生成的累计绑定也需在最终入口验收中重跑；当前不能宣称旧尾帧拼接已经在界面或成片路径修复。


## 最终合成消费累计音视频

最终合成已调用累计来源解析器。时间线上相邻且属于同一原生链的段，统一从链末端累计媒体提取各自准确的新增时间范围；独立切镜、另一分支及重排不会把累计前缀重复加入时间线。模型原声仅在 clip ID、segmentId 与当前采用的原声音频文件一致时切换到相同累计媒体的对应时间范围，保留用户的开始位置、裁切、音量和静音参数。合成前后复核视频段和时间线快照，期间发生编辑则拒绝采用过期结果。

三项相关回归通过：连续三段范围守恒、切镜/分支/重排，以及真实 FFmpeg/SQLite 合成。真实回归把旧预览设为蓝色静音，累计结果设为绿色测试音，最终 107 帧输出确实为绿色且有测试音，证明画面和原声均采用累计来源。该测试是合成机制验收，不是 H3 完整短剧视听验收。前端预览仍需接入相同范围，真实 H3 多段生成至最终合成仍需重跑。

本轮首次全量服务端类型检查被并行 Codex 测试中的两处 `safeParse` 类型错误阻断；未修改这些无关测试，完成媒体测试后复跑全量类型检查已通过。


## 四段真实入口、累计合成与浏览器预览

## 静音对照与原声音轨刷新缺陷
