# 《三体》红岸两分钟样片制作记录

本次交付是红岸“不要回答—主动回复”的压缩改编，采用原创面孔、布景和改写台词。实际生成十二段视频，剪为十三个片段，共 120 秒；同一警告段拆出三秒冷开场，其余范围不重复使用。

用户实看反馈：约 49–50 秒雪景外景人脸变形，整体声音一般，当前视听质量未通过。下述解码、播放与识别结果仅为技术检查，后续对照及未解决条件见[质量复核](threebody-quality-followup.md)。原成片保持不变。

最终文件的逐帧时间戳、帧数、分辨率、帧率和音轨时长已核对。完整 FFmpeg 解码退出码为 0；独立浏览器页面播放到 120 秒结束，记录 7200 帧、零掉帧。十二处段内切镜分别检查了切点附近八帧；片名、长句字幕、发射键与结尾另行抽查。浏览器检查使用静音，不能当作主观听审。

## 实际制作链条

| 阶段 | 本次采用方式 |
| --- | --- |
| 图片 | 原生生图生成一张角色三栏身份板，以及机房、天线、林场三张场景图；保存实际文件和完整提示 |
| 分镜与预演 | 十二个完整分镜段，各自对应一个制作任务；粗模只承担机位、大体调度和切点参考 |
| 视频原片 | 现有媒体执行器的 H3 REF2VA、PDD Ref8、480p／24fps；逐段检查后采用 |
| 声音 | Qwen3 TTS CustomVoice 的 Serena、Uncle_Fu；Music3 独立配乐；MOSS 机房、林场风声、键盘和按钮声音 |
| 剪辑 | 按实际原片选取范围，不通过变速凑时长；模型原声不入最终混音 |
| 提质 | 采用范围先提交 FlashVSR Turbo 超分，再由组合能力补到 60fps；逐段输出 3840×2134 |
| 成片 | 保持比例补边至 3840×2160，修正跨切插值，再叠加片名和字幕，最后单独封装 120 秒混音 |

本次直接由 480p 进入后处理，没有经过 768p 重生成或 latent 精修。主要表演为监听、默读和敲键；警告是接收信息的听觉化，回复是内心旁白，不能作为音频驱动口型同步的验证。

声音先检查单独配音的识别内容，再用 ForcedAligner 定位字幕。混音后再次转写，发现第一次警告的“不”被漏识；降低该句前后的配乐后，最终混音全部台词经去标点及“他／她”同音归一后匹配。该结果支持对白可识别性，不代替自然度、情绪、音色或音乐的主观评价。最终混音约为 -16.83 LUFS、-4.18 dBTP。

## 修正与复现边界

- 林场粗模起初残留机房定位物，在任务尚未推理时撤回，修正预演并补具体林场图后生成。
- 发射前停顿的首版提前碰到按钮，重做同一任务，采用侧脸与伸手停顿；原记录保留。
- RIFE 在低差异硬切处插出混合帧。本片按实际原片确认十二处段内切点，去掉各两帧跨切插值，以前一干净帧保持到新镜头，维持 60fps 与原有时钟。该修正发生在本次成片编码中，不能宣称现有通用提质服务已经自动完成切镜处理。
- 导演台会将原始输出以 x264 CRF16 等参数重新编码为任务预览，因此任务预览与执行器原片哈希不同。十二段实际采用原片均匹配对应执行器结果的 SHA256；工程包另存 `raw-clips/` 与实际提质输入 `adopted-clips/`，剪辑配方按实际采用文件引用。
- 当前工程的部分场景依赖已变化，原生导出因续接状态失效返回 `DIRECTOR_H3_STATE_INVALID`。没有清除待检查标记或伪造旧快照；交付普通 v3 文件工程 ZIP，保留媒体和输入，明确省略 latent 续接状态。

成功任务账本包含十三次 H3 视频执行（含一次重做）、十二次提质、五次 TTS、一次配乐、四次 MOSS 和十二次识别／对齐；另有七条早期 TTS 失败、一次视频排队撤回及三次提质排队撤回记录，未隐藏。成功 H3 任务执行耗时合计约 48.4 分钟，提质约 105.0 分钟；这是执行器报告的执行秒数合计，不能当作端到端耗时或纯 GPU 占用时间。

本片仍有次要设备布局、手别与表情等源片连续性差异，按钮动作也不是严格机械仿真。叙事节奏、声音听感、细闪和整体观感等待用户验收；单角色、固定主场景的两分钟片段不能证明长小说多角色、多集无人值守质量已成立。现有导演标准渲染器仍为其原有规格，本次 4K 文件由实际采用素材另行合成，不代表导演渲染接口已经新增 4K／60fps。

本次没有修改应用或执行器代码，没有新增服务或端口。复现参数与实际执行上下文见工程包的 `deliveries/preflights/`、`enhancement-preflights/`、`generation-ledger.json`、`source-provenance.json` 和 `recipe.json`。
