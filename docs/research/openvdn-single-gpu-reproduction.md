# OpenVDN 单卡复现研究

## 结论与范围

OpenVDN 继续列为优先研究对象。它同时减少采样次数和注意力计算量，有不同于 PDD 的技术价值。当前已完成源码、模型索引、真实权重投影检查，以及首轮三项和第二轮八项隔离视频生成。混合注入方案已有单场景可运行及加速证据，但对白时序仍不达标。仅使用既有环境和权重创建临时副本，没有下载新权重或修改正式服务。不能将社区剪枝量化实验称为作者完整复现或生产质量验收。

分两条路线推进：作者完整模型用于建立可信基准；现有 ComfyUI 剪枝量化模型用于低成本适配实验。本次结果支持优先继续“普通层 merge，仅 AdaLN 重新注入”的研究方案；它仍需检验时间嵌入近似和量化影响，不能直接替代作者基准。

## 51 项增量缺失的根因

现有实验导出器 `server/src/h3-experiment-workflows.ts` 选择 `lora_mode=merge`。社区节点 `vdn_h3/apply.py` 对剪枝基座主动过滤 AdaLN 增量，因为压缩后的时间条件投影无法直接接受原始形状的 LoRA。

本次使用 safetensors 库只读检查真实权重形状：

| 项目 | 结果 |
| --- | --- |
| default 适配器 | 208 对 LoRA，AdaLN 为 0 对 |
| turbo 适配器 | 363 对 LoRA，其中 AdaLN 为 51 对 |
| turbo 的 AdaLN A 矩阵 | 示例为 `[16, 2688]` |
| 当前 FL2VA 剪枝基座对应权重 | `[96768, 8]` |

因此不能通过忽略警告、重命名权重或普通 reshape 解决。缺失的是 Turbo 训练的实际增量，既有样片不能作为作者八步模型的完整结果。

社区节点已有 `bypass` 和时间嵌入网格重新注入代码，需要相邻 `ComfyUI-MiniMax-H3-Turbo/h3_silu_temb_grid.safetensors`。本次检查的旧隔离实验目录中没有该目录。切换一个参数仍不足以完成修复；还要核对网格来源、时间/音视频 shift、插值行为、全部增量的应用数量及显存成本。社区注释中的质量判断不作为本机证据。

原始只读结果：`.tmp/openvdn-research/local-adapter-audit.json`。

## 增量投影与三项真实生成

从现有固定 Turbo 节点 `4274783a23afcfdbea3b4876cb79effd6c510785` 找到已存在的网格，SHA256 为 `30eb3c2cc7fb6b470d9717ff840d359313ac27cd64b705e32da1baa10f72d6a8`。网格形状 `[1025,2688]`，剪枝基座时间表形状 `[1025,8]`。没有重新下载或修改该文件。

CPU 对全部51项真实 A/B 权重做六个时间点的投影对照，每项修正均非零。现有节点优先从最近时间表行取原始嵌入，相对线性插值参考的最大修正范数误差约0.0663%；改用其共享线性插值分支时最大绝对差约 `4.77e-7`。这只是给定权重和时间点的数值检查，不能推导相对原作者模型的全程误差或画质。

社区节点 README 明确记录八步 DMD 对全量 bypass 的 bf16 舍入误差敏感。因此补做“普通层仍 merge，仅无法合并的 AdaLN 重新注入”实验。研究补丁只应用到 `.tmp/openvdn-research/runtime`；增加运行时检查，嵌入缺失、行数不符或首次修正无效时直接失败，并记录每项实际执行。该补丁不属于生产配方。

三项均使用同一参考图、提示、种子314159、960×544、124帧、24fps、八步 er_sde/beta；实际是单首图 I2VA，不是同时提供首尾图的 FL2VA 验收。

| 实验 | 完成耗时 | 整卡采样峰值 | AdaLN 实际执行 |
| --- | ---: | ---: | ---: |
| 原 merge 对照 | 72.842秒 | 30305MiB | 0，保留原跳过行为 |
| 全量 bypass | 76.888秒 | 29701MiB | 51项 |
| merge + AdaLN 重新注入 | 74.875秒 | 29819MiB | 51项 |

两种重新注入方式记录的51个首次修正范数逐项相同。三项均输出124帧、约5.167秒且包含音轨；实验有首次载入、缓存状态和审计开销差异，只能描述观察耗时，不能据此宣称某条路线稳定快多少或更省显存。

相对原 merge，全量 bypass 的解码画面 SSIM 为0.896774，混合方案为0.986807；两者均没有与原 merge 完全相同的解码帧，解码音频哈希也不同。说明增量产生了可测变化，混合方案在此样例更接近原 merge；SSIM 不表示质量优劣。已查看三组1fps接触表，未见整体崩坏，人物表情存在差异，完整动作、听感、台词和口型仍未验收。

## 第二轮：三种子与长首尾帧

固定同一人物、场景、首图与960×544输出，分别对照基础20步（res_multistep/simple、SageAttention）和混合注入VDN八步（er_sde/beta、grouped窗口注意力，fast_kernels关闭）。每组内提示、种子、帧数及输入图完全相同；每项开始前检查相关队列，并释放实验实例的模型缓存。它是当前两条应用配方的对照，不是只修改步数或注意力内核的单变量消融。

| 任务 | 种子 | 基础20步 | VDN八步 | 观察加速 |
| --- | ---: | ---: | ---: | ---: |
| 首图，124帧／5.167秒 | 314159 | 95.128秒 | 74.820秒 | 1.271× |
| 首图，124帧／5.167秒 | 271828 | 95.155秒 | 72.938秒 | 1.305× |
| 首图，124帧／5.167秒 | 161803 | 95.203秒 | 74.855秒 | 1.272× |
| 首尾图，345帧／14.375秒 | 314159 | 380.276秒 | 175.997秒 | 2.161× |

三组短片的配对中位加速为1.272×。八项均成功，总记录生成耗时1064.372秒；四次VDN各记录51项AdaLN实际执行，共204项。短片VDN整卡采样峰值30175–32053MiB，基础版31171–31309MiB；长片分别30787MiB、30681MiB。没有稳定省显存证据，峰值仍包含其他驻留进程。

长组同时增加时长、尾帧和对应提示，不能将相对短组的收益变化全部归因于长度。尾帧来自首轮 `merge-live/output-0.mp4` 的第123帧，是已有生成素材；两条配方使用相同尾帧，尚不代表不同角色、镜头或真实拍摄素材的普遍表现。

### 画面与声音检查

- 已检查全部八项第0帧及之后每24帧的接触表。未观察到新增人物、分屏或整体身份丢失；表情与动作时序有差异。整片FFmpeg场景变化诊断最高分均低于1（记录阈值10），未检出明显突变；该指标不能证明运动自然或不存在细微跳变。
- 首帧相对缩放参考的SSIM约0.792–0.808；长片尾帧基础版0.897446、VDN为0.878566。输入图有引导作用，但输出不是像素级复现，也不能据此宣称首尾严格一致。
- 使用已有本地Qwen3-ASR与ForcedAligner，GPU计时结束后离线CPU运行。八项均识别为一次“别担心，等我回来。”，未在转写中出现重复或漏字。这是单一识别器的辅助证据，不等于完整听感验收。
- 提示要求对白位于1.5–3.5秒；短片自动对齐约2.24–2.64秒开始、4.48–4.64秒结束。长片基础版5.68–9.12秒、VDN为5.68–8.96秒，均明显偏晚。两条配方都存在时序问题，不能归因于VDN独有，也不能把台词完整当成时序通过。
- 仍未完成完整常速视听、音色与音素级口型验收；本轮没有768p、Ref2VA、多人物或长片多种子结论。

结构化结果、输入哈希、逐项显存、语音转写与对齐见[第二轮报告](../../media-executor/examples/h3-evaluation/openvdn-research/matrix.json)。原始媒体与诊断文件在 `.tmp/openvdn-research/matrix/`。第二轮结束后8192进程已关闭，显存和原有两实例队列恢复到先前状态。

研究判断：混合注入值得保留为独立实验候选，这组长首尾帧已有较明确的等待时间收益。下一阶段应优先补作者采样/优化内核与完整模型基准的对齐，再扩大场景质量检查；当前不直接升级为默认配方。现有社区grouped实现没有启用作者的整套融合内核，结果不代表OpenVDN性能上限。

## 作者单卡路线与真实资源需求

作者 `infer_diffusers.py` 支持文本、首帧和首尾帧，提供 `--offload_dit` 分块卸载；默认八次模型评估，内部传 `num_inference_steps=9`，不能再手动多加一步。作者称 345 帧任务峰值约 20GB 显存，这是作者数据，尚未本机验证。

依赖需要独立 Python 3.12 环境。当前作者推荐 Torch 2.13.0 CUDA 12.9，项目固定 Triton 3.7.1、FlashAttention 4.0.0b26 等；不能套用已有 ComfyUI Torch 2.11 环境。作者安装脚本在 Diffusers `3a2f35d` 基础上应用两份补丁：AdaLN SiLU 显式 FP32，以及流式卸载时将 buffers 一并移回 CPU。FP8 权重使用 buffers，遗漏后者可能导致显存持续累积。

按两个固定模型仓库的文件元数据，文本输入的完整路径主要需要以下磁盘文件（十进制 GB）：

| 组件 | 大小 |
| --- | ---: |
| OpenVDN 原始 transformer | 66.281 |
| MiniMax 文本编码器 | 66.727 |
| 视频 VAE | 10.416 |
| 音频 VAE | 0.605 |
| 八步线性分支及两个适配器 | 5.465 |
| 合计，不含环境、缓存和输出 | 约 149.494 |

模型索引跨仓库引用文本编码器和 VAE；作者仓库的约 82GB 下载说明不等于任意文本输入的全部磁盘成本。选择具体 workflow 可避免额外下载 Ref2VA transformer，但不消除文本编码器。FP8 在加载合并后转换，也不意味着只下载 FP8 大小的文件。

本次宿主快照：RTX 5090，32607MiB 显存、4834MiB 已用、27268MiB 空闲；8189/8190 队列均为空。系统内存约124GiB、可用102GiB；NVMe 空闲约113GiB。已有部分增量可复用，但完整路径仍需先盘点所有可复用组件；CPU 流式卸载可能同时保留大模型，102GiB 可用内存也不能直接判为足够。不得自动删除现有模型腾空间或把新增权重写到机械盘。

可研究拆开文本编码与视频推理进程，使用作者支持的提示 embedding，降低同时驻留内存；必须核对编码来源与 dtype，不把 ComfyUI 量化编码结果假定为作者输入。固定提示缓存可用于首次 smoke，但不足以验收任意提示输入。

## 可复现性与能力边界

- 模块索引中的多个 component revision 以及 VDN 内部 base revision 为 null；只固定顶层仓库版本不够。实验清单必须为跨仓库组件、内部 base、远程模型代码和所有依赖分别固定版本或采用校验过的本地路径。
- 作者模型加载器对找不到的 LoRA 目标会报错，但仍应核对实际应用数量、形状和完整参数集合，不能只以“没有异常”为验收。
- 作者路线使用两份自带适配器，不叠加 PDD 或 LightX2V。其状态不与当前 H3 原生续拍状态混用。
- 作者明确支持 T2VA、I2VA、FL2VA、L2VA；[Ref2VA 问答](https://github.com/OpenVDN/vdn-minimax-h3/issues/5)将专用参考模型训练与社区扩展区分。先验收首尾帧，再单独评估多图、故事板与音频参考。
- 8×B200 的 11.23 秒是稳定态去噪时间，排除了加载、预热、解码与编码；不能直接作为单张 5090 点击到成片的速度预期。

## 下一步实验顺序与验收

1. 完成作者 ModelScope 最新同仓映射、组件复用及磁盘/RAM预算，生成固定文件清单；完整路线不直接执行会自动拉取全部组件的示例命令。
2. 已完成三种子短I2VA与一组长FL2VA基础/混合方案对照及离线台词检查；继续多场景、长片多种子和完整视听验收，单独处理对白时序问题。尚不能推广成Ref2VA、续拍或全模式能力。
3. 建立作者完整路线的独立环境，以单个短 I2VA 任务验证加载、八次采样、声音与输出，再做真实 FL2VA。完整基准不使用剪枝基座。
4. 当前社区配方的基础/VDN短片与约14秒对照已完成；作者完整路线仍需重新建立相同条件基线。Ref2VA PDD 的历史耗时不能充当FL2VA同条件基线，也不能用当前社区结果推算作者优化内核的速度。
5. 分开记录首次编译、模型加载、热启动去噪、解码/编码、完整落盘耗时、显存和 CPU 内存；每组至少保留三种子，不以一次成功推导成功率。
6. 完整看听身份、动作、首尾约束、对白完整性和口型，再计算含失败重试的采用成本。通过后才考虑作为中立服务中的独立运行时/配方，由同一 `media-generation` Skill 描述能力与限制。

目前已有累计十一项单卡实测和限定场景下的观察加速比，但没有普遍质量保证或作者完整复现结论。研究文档不改变现有默认配方或正式服务。
